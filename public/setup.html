连接你的 Linux QQ

本机配置 SSH → 只读预检 → 选择 QQ 主窗口 → 保存并连接。不会启动第二个 QQ，不捕获整个桌面。

1 · 本机 SSH 连接

只填写本机密钥路径，不粘贴密钥内容。私钥不会上传；加密密钥先加入 ssh-agent。当前向导使用密钥认证，不保存 SSH 密码或口令。

首次 SSH 连接失败怎么办？
  1. 远端需要 Linux 图形会话、SSH 服务，以及已运行且可见的 QQ（X11/Xwayland）。SSH 用户应与 QQ 所属用户一致。
  2. 在本机终端首次执行 ssh -p 22 用户名@主机，与远端核对主机指纹后才信任。程序不会自动跳过主机密钥检查。
  3. 加密私钥先执行 ssh-add /本机/私钥路径；Unix 私钥权限应为 600。
  4. 再执行 ssh -o BatchMode=yes -p 22 用户名@主机 true，无需交互成功后返回预检。端口按实际修改。
高级：远端 VNC 密码文件

这是远端文件路径，不是密码。留空会自动检查远端 $XDG_RUNTIME_DIR/x11vnc.pass（通常是 /run/user/<UID>/x11vnc.pass）和 ~/.config/qq-window-viewer/vnc.pass，不需要猜路径。

预检失败时也可以保存本机填写草稿；这不会保存为可连接配置，也不会启动远端服务。

预检只读取当前用户 QQ 进程及 X11 窗口元数据、依赖状态和密码文件权限；不读取聊天文字、截图或剪贴板，不安装软件、不启动服务。

预检结果

    仅列出当前用户的 QQ 普通可见窗口，并核对进程。一个候选时自动选中，多个候选时请按 XID / 尺寸选择；不会按最大窗口猜测。可暂时隐藏其他 QQ 窗口再预检。检测到进程不代表 QQ 已登录。

    只自动恢复到同一 QQ 可执行文件、类名和实例名下唯一的普通窗口；有歧义时暂停并要求重新选择。恢复只在本次点击连接后有效，主动断开会停止。

    远端缺少依赖、看不到 QQ 或不知道怎么准备？

    在远端做一次准备（不会自动执行）

    CachyOS / Arch：sudo pacman -S --needed openssh x11vnc python libx11（仅定向安装，不执行全系统升级）。Debian / Ubuntu：安装 openssh-server x11vnc python3 libx11-6。先确认发行版及软件仓库状态，再自行执行。

    按系统方式启用 SSH 服务，并只对可信网络开放 SSH；不要开放 VNC 端口。QQ 必须在同一用户的桌面会话中运行并显示。

    在远端终端创建专用 VNC 密码文件（命令交互输入，勿在命令行写明文密码）： 

    mkdir -p ~/.config/qq-window-viewer
chmod 700 ~/.config/qq-window-viewer
x11vnc -storepasswd ~/.config/qq-window-viewer/vnc.pass
chmod 600 ~/.config/qq-window-viewer/vnc.pass

    如果文件已存在，请先备份，不要直接覆盖。连接时在本软件密码弹窗输入同一个 VNC 密码。VNC 密码文件只是可逆混淆，不可公开。

    分清这几种状态

    • SSH 失败：检查网络、SSH 服务、端口、用户名、主机指纹和 agent；不要关闭主机密钥检查。
    • QQ 未运行：在远端手动启动已有 QQ；本工具不会启动或登录 QQ。
    • QQ 在运行但无可见窗口：从远端托盘显示主窗口；确认 SSH 和桌面为同一用户。原生 Wayland 窗口不受支持，不能退回全桌面捕获。
    • 无法访问显示会话：确认 QQ 使用 X11/Xwayland，DISPLAY 和 XAUTHORITY 可从其进程读取；不要将 SSH shell 的空环境变量当作 QQ 后端证据。
    • 多个主窗口候选：手动选择或隐藏其他窗口后重试。不会仅凭进程名就开始采集。
    • 候选框 helper 未就绪：不影响主画面连接；IME 叠层是可选实验功能，需要另行部署 capture-ime，且只支持 Fcitx X11 popup。

    配置仅存于本机 ~/.config/qq-window-viewer/connections.json。保存前备份原文件；令牌、密码、私钥不写入此配置。当前仍需要系统 OpenSSH；安装包已内置 Node.js。
